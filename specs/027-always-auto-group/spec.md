## User Scenarios & Testing *(mandatory)*

### User Story 1 - 新增技能自动进入文件夹 (Priority: P1)

用户打开「插件 → 折叠skill → 配置」，勾选「始终分组」并保存。未分组的技能立即归组；之后安装、启用或新增技能时，新技能按前缀进入已有文件夹或新文件夹，用户不需要再点「按前缀自动分组」。

**Why this priority**: 技能随安装、升级与停用而增减；每次手动点按钮容易遗漏，目录随之变长。

**Independent Test**: 在开关已开启的 profile 中新增两个同前缀技能，检查配置页列表、模型目录与 `skill_search` 的结果。

**Acceptance Scenarios**:

1. **Given** 存在未分组技能 `blueai-a` 与 `blueai-b` 且「始终分组」未勾选，**When** 勾选并保存，**Then** 立即新建文件夹 `blueai` 并包含两者，无需再点按钮。
2. **Given** 「始终分组」已开启且存在文件夹 `lark`，**When** 新增技能 `lark-im`，**Then** `lark-im` 属于 `lark` 文件夹，模型目录与 `skill_search` 都反映该变化。
3. **Given** 「始终分组」已开启且技能集合没有变化，**When** 插件收到一次变化通知，**Then** 配置内容保持不变。

---

### User Story 2 - 开关关闭后恢复手动分组 (Priority: P2)

用户关闭「始终分组」并保存，之后技能变化只更新未分组列表。用户仍可点「按前缀自动分组」手动整理。

**Why this priority**: 开关必须可逆；用户需要保留手动控制的路径。

**Independent Test**: 关闭开关后新增技能，确认配置不变；再点手动按钮，确认结果与自动分组一致。

**Acceptance Scenarios**:

1. **Given** 「始终分组」已关闭，**When** 新增技能，**Then** 不执行自动分组，该技能留在未分组。
2. **Given** 「始终分组」已开启，**When** 点「按前缀自动分组」，**Then** 结果与自动分组一致，成员不重复。
3. **Given** 「始终分组」已开启，**When** 关闭并保存，**Then** 后续技能变化不再触发分组。

---

### User Story 3 - 失败时不破坏现有分组 (Priority: P3)

技能读取失败或配置无法写入时，插件保持当前分组，用户看到的分组与目录不受影响。

**Why this priority**: 后台写入容易在失败时留下半成品；现有分组是用户资产。

**Independent Test**: 让配置写入被拒绝，触发一次技能变化，检查配置内容与会话目录。

**Acceptance Scenarios**:

1. **Given** 配置不可保存（只读或被更高层覆盖），**When** 技能集合变化，**Then** 现有分组保持不变，日志记录原因。
2. **Given** 技能读取失败，**When** 收到变化通知，**Then** 跳过本次自动分组，下一次变化重新尝试。

### Edge Cases

- 新技能名不含 `-`，或首段前缀下只有 1 个成员：沿用现有规则，留在未分组。
- 新建分组名与已有文件夹同名：合并进已有文件夹，不创建重名文件夹。
- 技能被移除：文件夹保留该成员名，模型目录与检索不再显示它。
- 用户把技能移出文件夹：下一次自动分组按同样规则再次分回；需要例外时关闭开关。
- 配置页有未保存草稿时发生自动分组：页面保留草稿，保存时以草稿为准。
- 配置页只读时，「始终分组」勾选框禁用。
- 配置页的技能列表尚未加载完成时，开关状态照常显示；自动分组由插件在后台执行。
- 手动按钮与后台自动分组几乎同时发生：以最后一次写入为准，两者都不产生重复成员。
- 一次通知包含多个新增技能：按一次分组处理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 配置页「按前缀自动分组」右侧 MUST 提供「始终分组」勾选项，并用一句说明写清它与按钮的区别。
- **FR-002**: 「始终分组」默认 MUST 为未勾选；未勾选时插件行为与现状一致。
- **FR-003**: 勾选状态 MUST 保存在插件配置中，页面刷新与会话重启后保持。
- **FR-004**: 勾选并保存后 MUST 立即执行一次自动分组，结果写入插件配置，并立即作用于模型目录折叠与 `skill_search`。
- **FR-005**: 开关开启期间，技能集合每次变化后 MUST 执行一次自动分组，结果写回插件配置并立即生效；插件启用与打开配置页时不额外执行。
- **FR-006**: 自动分组 MUST 使用与配置页列表同源的全局技能；项目级技能不参与。
- **FR-007**: 自动分组 MUST 与「按前缀自动分组」按钮行为一致：只处理未分组技能，先按文件夹名匹配，其余按 `-` 分段最长公共前缀合并，成员不少于 2 个才成组；已有文件夹的名称、简介、顺序与成员保持不变。
- **FR-008**: 技能集合没有变化时 MUST NOT 写入配置。
- **FR-009**: 开关关闭后 MUST 停止自动分组；「按前缀自动分组」按钮的行为不变。
- **FR-010**: 配置写入失败 MUST 保持当前分组并记录日志；下一次技能变化重新尝试。
- **FR-011**: 技能读取失败 MUST 跳过本次自动分组并保持当前分组。
- **FR-012**: 用户把技能移出文件夹后，下一次自动分组 MUST 按同样规则再次把它分回；需要例外时用户关闭开关。
- **FR-013**: 自动新建的文件夹 MUST 使用空简介。
- **FR-014**: 配置页存在未保存草稿时，后台自动分组 MUST 照常写入；页面保留草稿，保存时以草稿为准。保存被拒时页面保留草稿供再次保存。

### Key Entities

- **始终分组开关**：插件级布尔设置，默认关闭，随插件配置保存。
- **技能集合**：当前全局技能名集合，与配置页列表同源。
- **文件夹**：名称、简介与成员技能名；自动分组只追加成员与新建文件夹。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 勾选「始终分组」并保存后，现有未分组技能立即归组并写入配置。
- **SC-002**: 开关开启时新增 `lark-` 前缀技能，在不打开配置页的情况下，下一次会话的目录把该技能折进 `lark` 文件夹。
- **SC-003**: 开关关闭时技能变化不写配置；配置内容与修改时间都不变。
- **SC-004**: 技能集合重复通知不产生额外写入。
- **SC-005**: 自动分组后，用户已有文件夹的名称、简介、顺序与成员保持不变。
- **SC-006**: 开关状态跨页面刷新与会话重启保持。

## Assumptions

- 插件配置可写；不可写的 profile 下开关保存失败，按现有保存失败提示呈现。
- 技能集合指全局技能名集合，与配置页列表同源。
- 现有分组规则保持不变，本次只增加触发方式。
- 项目级技能保持原样，不参与折叠与自动分组。
