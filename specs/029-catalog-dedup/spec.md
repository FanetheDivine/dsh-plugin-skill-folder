## Background（排查结论）

### 触发条件

宿主 `@deepseek-ai/dsh-tool-skill` 在每个步骤重新读取技能快照，按「条目的名称与描述 + 发现是否完整」合成指纹，与会话中已可见的那份目录比较，指纹不同就重发整份目录并标记为更新（`source.update = true`）。插件在 `agent/pre-step` 改写这条消息，并在宿主标记更新时使用「The available skill catalog changed.」首句。

### 根因

1. 指纹把「发现是否完整」算进去：条目完全相同、仅该标记不同，指纹就不同。
2. 宿主技能注册表只在完整观测时写缓存，发现期间目录版本变化或某个 provider 出错时返回「不完整」且不缓存，于是该标记在轮次之间来回抖动。
3. 每步的新消息批次都被宿主作为新节点追加进会话可见面：重发的目录不会被上一条取代，重复块因此永久累积。
4. 插件按宿主的更新标记选首句并照原样折叠，没有任何一层判断「折叠后呈现给模型的内容是否已经出现过」。

### 实机证据

本次会话的持久记录：17 条目录消息，条目始终是同一组 101 条（条目内容摘要恒定），只有完整标记交替 true/false，指纹在两个值之间来回跳。同期未出现抖动的会话（同一插件、同一 profile）全程只有 1 条目录消息。

### 判定信息来源的约束

`agent/pre-step` 的 `messages` 只包含本步骤从收件箱取出的新消息，宿主把目录消息放进这个新批次。插件在该监听里看不到之前轮次的目录消息，所以「是否已经呈现过」无法只靠本轮消息列表判断，需要 D-001 选定的来源。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 目录不变时只出现一份折叠目录 (Priority: P1)

用户在一个已配置文件夹的会话里连续多轮对话，技能目录没有增删。模型每轮看到的会话内容里，折叠后的技能目录块只有一份：首轮注入一次，后续轮次不再重复出现，也不再出现「The available skill catalog changed.」这句提示。

**Why this priority**: 这是缺陷本身，直接决定长会话的上下文开销。

**Independent Test**: 打开插件、配置文件夹后连续发若干轮消息，检查每轮请求里的折叠目录块数量与首句。

**Acceptance Scenarios**:

1. **Given** 会话首轮已注入一份折叠目录，**When** 技能目录条目与文件夹摘要都没变，用户再发一轮消息，**Then** 本轮模型可见内容中折叠目录块数量仍为 1。
2. **Given** 同上，**When** 宿主仍按「已变化」重发目录，**Then** 该重发既不出现在模型可见内容里，也不写入会话记录。
3. **Given** 同上，**Then** 「The available skill catalog changed.」首句出现次数为 0。
4. **Given** 会话在目录未变化期间被中断并恢复，**When** 恢复后继续对话，**Then** 折叠目录块仍然只有 1 份。

---

### User Story 2 - 目录真的变化时更新一次 (Priority: P2)

用户在会话中新增、删除技能，或在配置页改变文件夹分组，使折叠后的目录内容发生变化。模型在下一轮看到一份反映最新内容的折叠目录，并被告知目录已变化；变化之后内容再次稳定，后续轮次不再重复。

**Why this priority**: 去重不能以牺牲目录更新的及时性为代价。

**Independent Test**: 在会话中途改变技能或文件夹配置，检查下一轮的目录块内容与首句，再检查其后若干轮。

**Acceptance Scenarios**:

1. **Given** 会话已有一份折叠目录，**When** 保存文件夹配置使某个文件夹的成员集合或简介变化，**Then** 下一轮模型看到的折叠目录是变化后的内容，且只出现一次。
2. **Given** 会话已有一份折叠目录，**When** 技能被新增或移除，**Then** 下一轮出现更新后的目录，首句说明目录已变化。
3. **Given** 目录内容发生变化，**When** 变化之后的轮次内容再次稳定，**Then** 后续轮次不再重复注入。

---

### User Story 3 - 原生行为与既有边界保持 (Priority: P3)

插件的既有边界不变：没有折叠任何条目时原生目录逐字节不变；本 Agent 看不到 `skill_search` 时保持原生；快照读取失败时保持原生并在下一轮再试。

**Why this priority**: 修复只针对重复注入，不改变插件的最小介入原则。

**Independent Test**: 在未配置文件夹、或本 Agent 看不到 `skill_search` 的会话中检查目录消息是否保持原生内容。

**Acceptance Scenarios**:

1. **Given** 插件启用但没有任何条目被折叠，**When** 发送消息，**Then** 目录消息保持原生文本与原生字段。
2. **Given** 本 Agent 看不到 `skill_search`，**When** 发送消息，**Then** 目录消息保持原生。
3. **Given** 去重生效，**When** 检查保留下来的目录消息，**Then** 其条目字段仍为宿主发布的原值。
4. **Given** 会话记录不可读或没有历史目录消息，**When** 宿主发布目录，**Then** 插件按首次注入处理，呈现一条折叠目录。

---

### Edge Cases

- 宿主重发只因完整标记变化、条目不变：折叠正文相同，判定为已呈现，丢弃重发。
- 折叠正文相同但首句不同（首次发布与更新两种措辞）：按正文判定为相同。
- 文件夹配置修改使摘要文字变化、条目集合不变：正文变化，更新一次。
- 会话恢复、分叉或由外部写入的历史里含有目录消息：按该会话已呈现的内容判定，插件进程内没有跨会话记忆也不影响结论（依赖 D-001）。
- 会话记录里最后一条目录消息不是插件折叠的（原生文本，例如刚启用插件的会话）：按正文不同处理，注入一条折叠目录。
- 读取会话历史抛错或记录字段缺失：按未知处理，注入一条，绝不因此让整步失败。
- 消息列表中没有目录消息：不读取技能快照，行为与现状一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在折叠后的目录正文与本会话已呈现的最后一份目录正文相同时，丢弃这条重发的目录消息：模型该轮看不到它，会话记录也不新增它。
- **FR-002**: 系统 MUST 以折叠后的正文（未折叠条目列表 + 文件夹摘要）作为比较对象，忽略首句措辞与宿主的更新标记。
- **FR-003**: 系统 MUST 在正文相对已呈现那份发生变化时呈现新的折叠目录，使模型在 1 轮内看到最新内容。
- **FR-004**: 「目录已变化」首句 MUST 只在正文确实变化时出现（表述见 D-004）。
- **FR-005**: 系统 MUST 仅对宿主发布的技能目录消息做该判断，其余消息保持原对象与原顺序。
- **FR-006**: 系统 MUST 保持保留下来的目录消息的条目字段为宿主原值，改动仅限该消息正文与插件折叠标记。
- **FR-007**: 系统 MUST 保持既有边界：没有条目被折叠时原生目录逐字节不变；本 Agent 看不到检索工具时不介入；快照读取失败时保持原生并下一轮再试。
- **FR-008**: 系统 MUST 在会话历史缺失、不可读或读取失败时安全退化：呈现一条折叠目录，不抛错，不影响该步骤其余消息。
- **FR-009**: 判定来源 MUST 对同一会话的连续步骤稳定：会话恢复、分叉或进程重启后仍能得出「已呈现」的正确结论（取舍见 D-001）。
- **FR-010**: 文档 MUST 说明重复注入的宿主侧原因、插件的兜底行为与判定来源。

### Key Entities

- **折叠目录正文**: 一份目录在模型面前实际呈现的内容，由未折叠的条目（名称与描述）与文件夹摘要（名称、成员数、简介）组成，不含首句。
- **目录消息**: 宿主发布的技能目录会话消息，携带条目字段与是否为更新、发现是否完整的标记。
- **已呈现记录**: 本会话中最后一次呈现给模型的折叠目录正文，来源见 D-001。
- **去重判定**: 本轮折叠正文与已呈现记录之间的关系（相同 / 不同 / 未知）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在技能目录稳定的会话中连续对话 10 轮以上，模型可见内容里的折叠目录块数量为 1（修复前每轮 1 份，10 轮累积 10 份以上）。
- **SC-002**: 目录稳定的会话中，「The available skill catalog changed.」首句出现次数为 0。
- **SC-003**: 目录稳定的会话中，会话记录里新增的目录消息数量为 0。
- **SC-004**: 以本次实机会话为基准（单轮目录块约 2k tokens），20 步会话节省不少于 15 份重复块（约 30k tokens）。
- **SC-005**: 目录真变化的场景在 1 轮内生效，变化后的稳定轮次不再重复注入。
- **SC-006**: 既有折叠测试与新增去重测试全部通过，`pnpm check` 与 `pnpm build` 通过。

## Assumptions

- 宿主仍是每轮重算指纹并重发目录，插件不修改宿主。
- 用户可见的「上下文浪费」以模型实际可见内容为准；宿主持久记录里已有的历史重复块不在本次范围。
- 文件夹配置变化、技能增删都属于「目录正文变化」。
- 完整标记抖动由宿主的技能发现产生，与插件的分组配置无关。
