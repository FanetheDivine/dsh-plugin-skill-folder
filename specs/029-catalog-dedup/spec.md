## Background（排查结论）

宿主 `@deepseek-ai/dsh-tool-skill` 在每个步骤重新读取技能快照，把「条目的名称与描述 + 发现是否完整」合成指纹，与会话中已可见的那份目录比较，指纹不同就重发整份目录并标注为「已变化」。

- 指纹包含「发现是否完整」标记，条目本身没变时该标记也会改变指纹。
- 实机数据（本次会话的持久记录）：17 条目录消息，条目始终是同一组 101 条，只有完整/不完整标记在轮次之间来回切换，因此每轮都判为「目录变了」。
- 插件把宿主发来的目录消息改写为折叠文本，并在宿主标记为更新时使用「The available skill catalog changed.」首句；改写本身不产生目录消息，也不改 `source.entries`。
- 结果：宿主每轮重发，插件每轮折叠，会话里累积多份内容完全相同的折叠目录块。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 目录不变时只出现一份折叠目录 (Priority: P1)

用户在一个已配置文件夹的会话里连续多轮对话，技能目录没有增删。模型每轮看到的会话内容里，折叠后的技能目录块只有一份：首轮注入一次，后续轮次不再重复出现，也不再出现「The available skill catalog changed.」这句提示。

**Why this priority**: 这是缺陷本身，直接决定长会话的上下文开销。

**Independent Test**: 打开插件、配置文件夹后连续发若干轮消息，检查每轮请求里折叠目录块的数量与首句。

**Acceptance Scenarios**:

1. **Given** 会话首轮已注入一份折叠目录，**When** 技能目录条目与文件夹摘要都没变，用户再发一轮消息，**Then** 本轮模型可见内容中折叠目录块数量仍为 1。
2. **Given** 同上，**When** 本轮宿主仍按「已变化」重发目录，**Then** 该重发不出现在模型可见内容里，也不出现「The available skill catalog changed.」首句。
3. **Given** 会话在目录未变化期间被中断并恢复，**When** 恢复后继续对话，**Then** 折叠目录块仍然只有 1 份。

---

### User Story 2 - 目录真的变化时更新一次 (Priority: P2)

用户在会话中新增、删除技能，或在配置页改变文件夹分组，使折叠后的目录内容发生变化。模型在下一轮看到一份反映最新内容的折叠目录，并被告知目录已变化。

**Why this priority**: 去重不能以牺牲目录更新的及时性为代价。

**Independent Test**: 在会话中途改变技能或文件夹配置，检查下一轮的目录块内容与首句。

**Acceptance Scenarios**:

1. **Given** 会话已有一份折叠目录，**When** 文件夹配置被保存使某个文件夹的成员集合变化，**Then** 下一轮模型看到的折叠目录内容是变化后的结果，并且只出现一次。
2. **Given** 会话已有一份折叠目录，**When** 技能被新增或移除，**Then** 下一轮出现更新后的目录，首句说明目录已变化。
3. **Given** 目录内容发生变化，**When** 变化之后的轮次内容再次稳定，**Then** 后续轮次不再重复注入。

---

### User Story 3 - 原生行为保持 (Priority: P3)

没有安装或没有生效的会话保持宿主原样：插件不参与时目录按宿主自己的规则出现；插件参与但没有折叠任何条目时，原生目录逐字节不变。

**Why this priority**: 修复只针对重复注入，不改变插件既有的「最小介入」边界。

**Independent Test**: 在未配置文件夹、或本 Agent 看不到 `skill_search` 的会话中检查目录消息是否保持原生内容。

**Acceptance Scenarios**:

1. **Given** 插件启用但没有任何条目被折叠，**When** 发送消息，**Then** 目录消息保持原生文本与原生字段。
2. **Given** 本 Agent 看不到 `skill_search`，**When** 发送消息，**Then** 目录消息保持原生。
3. **Given** 插件去重生效，**When** 检查保留下来的目录消息，**Then** 其条目字段仍为宿主发布的原值。

---

### Edge Cases

- 同一轮的消息列表里出现多条目录消息（宿主替换首条、历史里另有旧条目）：模型可见的折叠目录块收敛为 1 份。
- 宿主重发只因「发现是否完整」标记变化、条目不变：视为目录内容未变，不重复注入。
- 目录内容相同但首句不同（首次发布与后续更新两种措辞）：按内容判定为相同。
- 文件夹配置修改使摘要文字变化、条目集合不变：视为内容变化，更新一次。
- 会话恢复、分叉或由外部写入的历史里含有目录消息：按当轮消息列表重新判定，不依赖插件进程内记忆。
- 消息列表中没有目录消息：不读取技能快照，行为与现状一致。
- 技能快照读取失败：保持原生目录，下一轮再试，行为与现状一致。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在折叠后的目录内容与本会话已呈现的目录内容相同时，让模型在该轮只看到 1 份该目录块。
- **FR-002**: 系统 MUST 仅在折叠后的目录内容相对已呈现的那份发生变化时，向模型呈现「目录已变化」的说明。
- **FR-003**: 系统 MUST 以折叠后的目录内容（未折叠条目列表 + 文件夹摘要）作为「是否变化」的比较对象，与首句措辞、宿主的更新标记无关。
- **FR-004**: 系统 MUST 仅对宿主发布的技能目录消息做去重，其余消息保持原对象与原顺序。
- **FR-005**: 系统 MUST 保持保留下来的目录消息的条目字段为宿主原值，改动仅限该消息的正文与插件折叠标记。
- **FR-006**: 系统 MUST 在没有任何条目被折叠时保持原生目录逐字节不变（现有行为）。
- **FR-007**: 系统 MUST 不依赖跨请求的进程内状态：同一份消息列表重复处理一次得到相同结果，会话恢复后仍成立。
- **FR-008**: 系统 MUST 在目录内容变化时呈现最新内容，被替代的旧目录块按 D-003 的决定处理。
- **FR-009**: 文档 MUST 说明重复注入的宿主侧原因与插件的兜底行为。

### Key Entities

- **折叠目录内容**: 一份目录在模型面前实际呈现的内容，由未折叠的条目（名称与描述）与文件夹摘要（名称、成员数、简介）组成。
- **目录消息**: 宿主发布的技能目录会话消息，携带条目字段与是否为更新、是否发现完整的标记。
- **去重判定**: 本轮目录内容与该轮消息列表中已保留的折叠目录内容之间的关系（相同 / 不同）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在技能目录稳定的会话中连续对话 10 轮以上，模型可见内容里的折叠目录块数量为 1（修复前为每轮 1 份，累积 10 份以上）。
- **SC-002**: 目录稳定的会话中，「The available skill catalog changed.」首句出现次数为 0。
- **SC-003**: 以本次实机会话为基准，单轮目录块约 2k tokens，修复后每轮节省 1 份以上重复块（10 轮以上会话节省约 18k tokens）。
- **SC-004**: 目录真变化的场景在 1 轮内生效，且变化后不再重复注入。
- **SC-005**: 现有目录折叠测试与新增去重测试全部通过。

## Assumptions

- 宿主仍是每轮重算指纹并重发目录，插件不修改宿主。
- 判定所需的信息全部来自当轮消息列表与当前技能快照。
- 用户可见的「上下文浪费」以模型实际可见内容为准，持久记录里的历史条目不在本次范围。
- 文件夹配置、技能增删都属于「目录内容变化」。
